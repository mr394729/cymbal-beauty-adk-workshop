# Associate development

Choose support that fits the work.

**User:** Manager; associate viewing their own record

**Example journey:** Dated activity → skill support → available learning → next-shift review

**Connected systems:** Fulfillment activity; coaching signals; learning management

**Decision:** Respond to the current development question and retain relevant context across the conversation. Dated measures, overlapping delay flags and completed learning support a practical recommendation. Associates review their own progress; managers support associates in their store. Available tools are selected as needed; a clarification may need no new read.

**Tools:** get_coaching_context; get_learning_options

**Data:** Personal activity snapshots include date, counts, target definition and overlapping delay flags. Learning snapshots supply actual module names, duration and completion.

**Evaluation references:** ops-development-1..3; ops-my-development-1..3; test_coaching_has_dated_units_and_self_scope. Verify personal scope, measurement period and that recommendations name available learning.

**Role research:** [Store-role research](../../docs/research/store-role-research.md). The connectors and records here belong to Cymbal; the source establishes the operational work, not a customer API contract.

The journey illustrates a capability. The current request, available evidence and user constraints determine the work; scenario selection does not prescribe a tool sequence.
